# [Reproducing the fixtures](@id fixtures)

The regression tests compare Syntomic.jl with three reference files in `test/fixtures`. Two of
them are generated from the authors' SageMath implementation of [AKN24, §7.1],
[antieau/kzpn](https://github.com/antieau/kzpn), by the scripts in `scripts/sage`; the third is a
transcription of tables of the paper.

## The fixture files

| file | contents | generated by | used by |
|:-----|:---------|:-------------|:--------|
| `sage_f1.json` | 41 cases with `f = 1` (unramified and ramified `E`, `n = 1`, two polynomials presenting the same ring, and `K_15(Z/81)`): `E`, the working precision, `h1`, `h2`, the `W`-matrices `can0`, `phi0`, `can1`, `red`, `redN`, `nablaOK` of Steps 5, 6, 8 and 9 and the matrices `nablaR`, `nablaN`, `canmphi`, `canmphiN` of Steps 7–10, with the p-adic precision of every entry | `scripts/sage/make_fixtures_f1.py`: the original code, with one instrumentation line that captures the intermediate matrices | `test/test_fixtures.jl`: cohomology (policies `:exponent` and `:adaptive`) and the `W`-matrices, compared modulo the smaller precision (`nablaOK` for odd `p` only) |
| `sage_fq.json` | 32 cases with `f = 2, 3` (brute-force `K_1` cases, `n ≤ e`, invariance families `E ↔ E^σ`, `E(z) ↔ E(az)`, perturbations of `E`, and `p = 5, f = 2`): `E` (exact integer coordinates), the matrix of `σ`, the `W`-matrices, `h1`, `h2`, and self-checks | `scripts/sage/make_fixtures_fq.py`: an in-memory copy of the original code patched for `f > 1` (Frobenius acts by `σ` on coefficients, see below) | `test/test_fixtures.jl`: cohomology (policies `:apriori` and `:adaptive`) and the `W`-matrices |
| `akn_tables.json` | [AKN24, Appendix A, pp. 61–64] (`K_r(Z/p^n; Z_p)`) and [AKN24, Fig. 1, p. 4] (integral `K_r` of `F_2`, `Z/4`, `Z/8`, `F_2[z]/z^3`) | transcribed from the paper (see its `provenance`) | `test/test_fixtures.jl`: the Appendix A rows with `n·i ≤ 24` (`n·i ≤ 64` in the long tier) and all of Figure 1 |

All p-adic numbers are stored as decimal strings. Every file has a `provenance` object (the
sources and their SHA-256, the date, and for the Sage fixtures the Sage version and the patches
applied) and a `conventions` object (the meaning of the fields and the index conventions of the
matrices). `test/test_style.jl` checks that the
fixtures contain data and page references only.

## Regenerating the Sage fixtures

The scripts run with the Python of SageMath 10.3 (the version the upstream code is verified with)
and read the upstream sources from `$KZPN_DIR`, a clean checkout of the upstream repository at
commit `ed381b4bf8df`:

```sh
git clone https://github.com/antieau/kzpn /path/to/kzpn
git -C /path/to/kzpn checkout ed381b4bf8df9522a12829ee0cbc9a2374949231
export KZPN_DIR=/path/to/kzpn
cd Syntomic.jl
sage -python scripts/sage/make_fixtures_f1.py --date YYYY-MM-DD   # test/fixtures/sage_f1.json
sage -python scripts/sage/make_fixtures_fq.py --date YYYY-MM-DD   # test/fixtures/sage_fq.json
```

Each run takes a few minutes. `make_fixtures_f1.py` runs every case in a fresh worker process
(`--jobs`, default 4; `--list` prints the case identifiers, `--only ID … --output PATH` reruns some
cases into another file). `make_fixtures_fq.py` also calls `julia --project=.` to check that the
Conway polynomials of Sage and Nemo agree (`--no-julia-check` skips this; `--only ID … --out PATH`
reruns some cases).

The scripts never import from, or write to, `$KZPN_DIR`: they read `prismatic_envelope.sage`,
`precision.py` and `matrix_functions.py` as text, apply anchored text patches in memory (every
anchor must occur exactly once, so a changed source fails loudly), preparse the result and execute
it in a private namespace. The patches are listed with their purpose in the `provenance` of each
fixture:

- `sage_f1.json` (trust level `sage-original`): one inserted line that hands the intermediate
  matrices to a capture hook; no value used by the computation is changed.
- `sage_fq.json` (trust level `sage-sigma-patched`): the upstream code assumes `f = 1`; the patches
  let Frobenius act by `σ` on the coefficients of `W(F_q)`, replace base-`p` digit sites by integer
  digits, and work around the arithmetic of power series over `Zq` in Sage 10.3. The cases are
  validated independently (brute force for `K_1`, the Hesselholt–Madsen formula for `n ≤ e`,
  invariance under `E ↔ E^σ` and `E(z) ↔ E(az)`, an integer Smith-form certificate, a rerun at
  higher precision, and negative controls without `σ`); see its `self_checks`.

## Provenance of the upstream sources

The file `scripts/sage/kzpn_upstream.py` records the upstream repository, the commit
`ed381b4bf8df9522a12829ee0cbc9a2374949231` and the SHA-256 of the three source files at that
commit. The `provenance` of both Sage fixtures contains

- `upstream`: the repository, the commit and these SHA-256;
- `kzpn_sha256`: the SHA-256 of the files actually read from `$KZPN_DIR`;
- `kzpn_matches_upstream_commit`: whether they agree (the scripts warn otherwise);
- `kzpn_git`: the `HEAD` of `$KZPN_DIR` and whether the three files are unmodified there (`null`
  if it is not a git checkout).

The committed fixtures were generated from a clean checkout of that commit. Regenerating them
reproduces every case (matrices, precisions, cohomology and checks) exactly; only the
`provenance` and the recorded Sage timings change.
